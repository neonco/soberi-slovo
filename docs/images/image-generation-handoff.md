# Передача: генерация вариантов картинок для «Собери слово»

Документ самодостаточный. Агент, который его читает, проекта не видит. Всё нужное здесь или в двух файлах, которые лежат рядом (см. §1). Владелец: Арсений. Общаться с ним по-русски.

## Готовый промпт для агента (вставить в opencode целиком)

```
Ты работаешь в Windows (PowerShell), видеокарта AMD Radeon RX 7800 XT 16 ГБ. Склонируй репозиторий https://github.com/neonco/soberi-slovo, убедись, что ты на ветке main и прочитай файл docs/images/image-generation-handoff.md целиком. Выполни его от начала до конца без остановок и вопросов: поставь stable-diffusion.cpp (Vulkan) и модель Z-Image Turbo по разделу 1, напиши пакетный скрипт по docs/images/image-prompts-v3.csv, сгенерируй все четыре пака по 2 варианта в prototype/images-v2/ и собери picked/, picked-1024/, picks.csv, контактные листы и notes.md по критериям раздела 9. Не меняй prototype/images/ и приложение, не коммить сгенерированные картинки. Если команда или имя файла из документа не подходит, найди актуальное через --help или Hugging Face, запиши в notes.md и продолжай. В конце коротко напиши, что готово и где лежит.
```

Агенту нужны только обычный терминал, Python (с Pillow) и интернет. Никаких особых инструментов или плагинов, всё делается командами в PowerShell.

## 0. Задача

Приложение: русская логопедическая игра для ребёнка 5 лет с задержкой речи (ОНР 2, есть признаки РАС). Нужна **картинка к каждому из 185 слов**. Сейчас есть два набора. Нужно сделать ещё три, по 185 слов, **по 2 варианта на слово**, чтобы потом выбрать лучшее и подменить в приложении.

**Режим работы: один непрерывный прогон. Вопросов Арсению не задавать и «показать и ждать ок» не делать.** Все решения уже приняты и записаны ниже. Если что-то неоднозначно, выбрать разумный вариант, записать в `notes.md` и идти дальше. Арсений смотрит результат только в конце.

Железо: **Windows, Radeon RX 7800 XT (16 ГБ VRAM, AMD)**. Модель: **Z-Image Turbo** (Apache 2.0). Инструменты и параметры в §1. Файлы вариантов сохраняются в 1024×1024, в `picked/` для приложения лежат копии 512×512, сид 42 для варианта _1, 43 для _2 (см. §4).

## 1. Инструменты, модель, параметры (Windows + RX 7800 XT)

Проверено по документации на 04.10.2026 (источники в конце). Скорость ниже **оценка**, замеров на 7800 XT в источниках нет: сделать замер на первых 5 картинках и записать в `notes.md`.

### Рекомендация: stable-diffusion.cpp, бэкенд Vulkan
Не зависит от ROCm (он на Windows для 7800 XT/gfx1101 капризен), одна папка с exe, **удобно гонять пакетно скриптом по CSV**. Работает на AMD через Vulkan-драйвер, обычного Adrenalin достаточно.

1. Скачать с GitHub-релизов `leejet/stable-diffusion.cpp` сборку для Windows **Vulkan** (`...win-vulkan-x64.zip`). Бинарь называется `sd-cli.exe` (в старых сборках `sd.exe`); флаги сверить через `--help`.
2. Файлы модели (искать на Hugging Face; точные имена репозиториев сверить на месте, они меняются):
   - диффузионная модель: **Z-Image Turbo, GGUF Q8_0** (~7 ГБ)
   - текстовый энкодер: **Qwen3-4B-Instruct-2507 GGUF Q4_K_M** (~2,5 ГБ)
   - VAE: `ae.safetensors` (FLUX VAE)
   Всё помещается в 16 ГБ с запасом. Если Q8 не стартует или качество плохое, Q6_K или Q5_K_M.
3. Команда (пример):
```powershell
sd-cli.exe --diffusion-model z_image_turbo-Q8_0.gguf --vae ae.safetensors --llm Qwen3-4B-Instruct-2507-Q4_K_M.gguf `
  --prompt "<prompt>" --width 1024 --height 1024 --steps 8 --cfg-scale 1.0 --sampling-method euler `
  --seed 42 --diffusion-fa --vae-tiling -o out.png
```
4. Для 185 слов написать небольшой скрипт (Python), который читает `image-prompts-v3.csv`, подставляет `prompt_<пак>`, гонит сиды 42 и 43, сохраняет в `prototype/images-v2/<пак>/слово_N.png`, **пропускает уже существующие файлы** (чтобы можно было возобновить), и сохраняет **как есть, 1024×1024, без уменьшения**. Уменьшение до 512 делается отдельно и только для `picked/` (шаг в §8).

### Запасной вариант: ComfyUI с ROCm
Официальная сборка ComfyUI Desktop для Windows с AMD ROCm (ROCm 7.1.1, при установке выбрать «AMD ROCm»). AMD публикует готовый плейбук именно для Z-Image Turbo (текстовый энкодер Qwen 3 4B, VAE, 4–10 шагов). Минусы: в анонсе пользователи пишут про падения и недозагрузку GPU, а в списке архитектур плейбука стоит gfx1100, а у 7800 XT это gfx1101, так что поддержка не гарантирована. Использовать, если Vulkan-путь не запустился. Весь пакетный режим там делается через API/очередь, сложнее.

### Не использовать
DirectML (медленно, устаревший путь), Draw Things и mflux (только Mac), FLUX dev (тяжёлый и медленный на 16 ГБ).

### Замена модели
Z-Image Turbo на этой связке работает, замена не нужна. Если Z-Image не запустится ни в одном из вариантов, запасная модель: FLUX.1 schnell GGUF Q4_K_S через тот же sd.cpp (4 шага, cfg 1.0), качество рисованных пака чуть слабее, но запускается.

### Параметры
| Параметр | Значение |
|---|---|
| Размер генерации и хранения | **1024×1024**, как есть (Z-Image обучена на ~1 мегапиксель, на 512 прямо качество хуже). Если слишком долго, 768×768 |
| Шаги | 8 |
| Guidance (cfg) | **1.0** (для Turbo обязательно, выше портит картинку) |
| Sampler | euler, scheduler по умолчанию (discrete) |
| Сид | 42 для `_1`, 43 для `_2` |
| Негативный промпт | **не используется** (при cfg 1.0 игнорируется), ограничения написаны прямо в промпте |

### Скорость (оценка, не замер)
Для RDNA3 уровня 7800 XT ждать порядка 10–30 секунд на картинку 1024² при Vulkan, 6–15 секунд при 768². Объём: 185 слов × 2 варианта × 4 пака = 1480 картинок, то есть примерно 4–12 часов чистого времени. Поэтому пачками с возобновлением (§8). Если выходит за 12 часов, сократить пак 5 (paper) до одного варианта и записать об этом в `notes.md`.

## 3. Шаблоны промптов

Готовые промпты по всем словам уже лежат в `image-prompts-v3.csv` (колонки `prompt_flat`, `prompt_photo`, `prompt_watercolor`, `prompt_paper`). Ниже шаблоны, из которых они собраны, чтобы агент понимал логику. `{o}` это колонка `object`, `{s}` колонка `scene`.

**Негативных промптов нет.** Z-Image Turbo идёт при cfg 1.0 и негатив не учитывает, поэтому все ограничения (один предмет, без текста, нужный фон) записаны в самом промпте как обычные предложения. Промпты написаны связным английским текстом, а не списком тегов: модель на базе Qwen лучше понимает именно так.

### Пак 2: Flat
```
A flat vector illustration of {o}, in the style of a children's educational flashcard. Bold thick dark outline, solid flat pastel colors, simple shapes, no shading, no gradients, no shadows. A single subject centered with margins, plain pure white background, no text, no letters.
```

### Пак 3: Photo (естественный фон)
```
A realistic photograph of {o}, {s}. Soft natural daylight, shallow depth of field, sharp focus on the subject, a single clear subject centered in the frame, whole subject visible, clean uncluttered composition, no text, no watermark.
```
Сцена `{s}` в CSV уже подобрана по категории слова (животные на траве, еда на деревянном столе, транспорт в естественной обстановке, люди в светлой бытовой обстановке и т. д.). Фон мягкий и нейтральный, предмет читается мгновенно. Люди: дружелюбные, естественные лица, без гримас. Для слов-действий ребёнок целиком, сбоку или со спины, лицо не обязательно.

### Пак 4: Watercolor
```
A soft watercolor illustration of {o} for a children's picture book. Gentle pastel colors, delicate brush strokes, visible paper texture, light washes, a single subject centered with margins, a pale soft watercolor wash background, no text.
```

```
A paper cut-out collage of {o}, made of layered colored construction paper with simple shapes and soft paper shadows, children's craft style, a single subject centered with margins, plain light cream paper background, no text.
```

## 5. Структура папок и имён

```
prototype/images-v2/
  flat/         ананас_1.png, ананас_2.png, апельсин_1.png …
  photo/
  watercolor/
  paper/
  picked/       слово.png   ← финальный выбор 512×512 для приложения, один файл на слово, без суффикса
  picked-1024/  слово.png   ← те же выбранные картинки в 1024×1024 (мастера)
  picks.csv     word,pack,variant,note
  notes.md      параметры, замечания, проблемные слова
```

Правила имён:
- **Файл = слово** кириллицей строчными, как в CSV (с «ё»: `вертолёт`, `самолёт`, `пёс`). Суффикс `_1`, `_2` через подчёркивание. Без пробелов.
- Файлы вариантов: PNG, 1024×1024, RGB (мастера). `picked/`: PNG 512×512 (как `prototype/images/`). `picked-1024/`: те же выбранные мастера без уменьшения.
- `picked/слово.png` совпадает по имени с `prototype/images/слово.png`, поэтому подмена в приложении сводится к замене папки или копированию файла. `picks.csv` фиксирует, из какого пака и варианта взято, чтобы можно было вернуться.
- В `prototype/images/` ничего не писать.

## 6. Как работать с каждым словом

1. Прогнать 2 варианта.
2. Быстро посмотреть сеткой (контактный лист, 185 слов × 2 варианта в одном или нескольких PNG на пак, чтобы Арсений листал глазами).
3. Автоотбраковка (отметить, не удалять): текст или буквы на картинке, больше одного предмета, предмет обрезан краем, лишние конечности/пальцы, не тот предмет, страшное или агрессивное.
4. Лучший вариант по слову записать в `picks.csv`.

## 7. Как отбирать лучшее

Критерии (по порядку важности):
1. **Ребёнок узнаёт предмет за секунду.** Типичный прототип (мороженое = рожок с шариком).
2. **Один предмет**, ничего отвлекающего, нет текста.
3. **Единообразие внутри пака.** Стиль, масштаб и положение похожи у всех слов.
4. Для людей: дружелюбно, без гримас.
5. Чистота: нет артефактов, лишних деталей.

Пробной десятки и остановок на согласование нет. Первые 10 слов каждого пака (кот, мяч, дом, банан, машина, гриб, мама, спит, ложка, пять) агент просто смотрит сам. Если стиль явно «плывёт» (текст на картинках, несколько предметов, фото вместо рисунка), поправить шаблон, записать в `notes.md` и пересоздать пак. Сид не менять.

## 8. Порядок работы (без остановок)

1. Прочитать этот файл и три исходных. Проверить, что в CSV 185 слов.
2. Поставить sd.cpp Vulkan и модель по §1, проверить на 1–2 словах, что запускается и нет падений. Замерить скорость на 5 картинках, записать в `notes.md`. Если Vulkan-путь не завёлся, перейти на запасной (ComfyUI ROCm).
3. Написать пакетный скрипт по §1 (читает `image-prompts-v3.csv`, пропускает готовые файлы, сохраняет 1024 без уменьшения).
4. Прогнать паки по порядку 2, 3, 4, 5, по 2 варианта на слово. Пачками (например, по 20 слов), сохранять сразу, чтобы прогон можно было возобновить. Следить за температурой видеокарты.
5. Автоотбраковка и выбор лучшего варианта по критериям §7, заполнить `picks.csv`.
6. Собрать контактные листы по каждому паку.
7. Собрать `picked-1024/` (копии выбранных) и `picked/` (те же, уменьшенные до 512×512 Pillow Lanczos), написать `notes.md`. Папки паков с мастерами 1024 в git не добавлять (оценка ~1–2 ГБ), хранить локально.
8. Сообщить Арсению, что готово, и где лежит.

## 9. Что считать готовым

- Каждый из паков 2, 3, 4, 5 содержит 185 слов × 2 варианта, 1024×1024, имена по §5.
- Контактный лист по каждому паку.
- `picks.csv` заполнен для всех 185 слов; 13 слов из §7 с пометкой `проверить`.
- `picked/` (512) и `picked-1024/` собраны и **по именам совпадают с `prototype/images/`** (185 файлов).
- `notes.md`: модель, шаги, сиды, шаблоны, что менялось, проблемные слова.
- Ничего не заменено в приложении и в `prototype/images/`. Подмену делает Арсений отдельным шагом.
